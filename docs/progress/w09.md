# W09: isolate the query worker

Scheduled November 22, 2026. Implemented November 23 as catch-up work. Tracks issue #16 and is based on the P04 branch while PR #15 is open.

The [worker contract](../query-worker.md) documents the isolated container, read-only input, limits, and verification. The first operation is an owned row count. W10 remains responsible for classifying and admitting analytical SQL, and neither the HTTP API nor a model can invoke the current worker.

The worker uses DuckDB 2.0.1, and the backend lockfile uses the same version. The Linux CI job runs the container probes in addition to the ordinary backend tests.
